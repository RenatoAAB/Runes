# Runes Debug - Runes, Tooltips, Highlights, Modifiers

## Purpose

Use this skill to start an implementer session quickly when a bug involves:
- rune behavior not matching design spec
- tooltip text order/phrasing mismatch
- highlight preview not matching actual targets/value sources
- modifier/slot interaction creating side effects on effects

This workflow is for practical debugging and correction, not broad refactors.

## Inputs Expected

Provide at least one of:
- rune id or rune name
- effect resource path
- user-facing incorrect tooltip text
- expected behavior from design/spec

Optional but useful:
- screenshot of tooltip/highlight
- exact trigger phase (ON_READ, ON_ROUND_END, ON_BUFF_RECEIVED, etc.)

## Mandatory Context First

Before changing code, collect context in this order:
1. Read [AGENTS.md](../../../AGENTS.md)
2. Read [.github/ARCHITECTURE.md](../../ARCHITECTURE.md)
3. Read [.github/COMMANDS.md](../../COMMANDS.md)
4. Read Obsidian spec note for the affected system/rune (source of truth)

If spec and implementation conflict, align with Obsidian spec unless user explicitly requests otherwise.

## Debugging Procedure

1. Confirm expected behavior
- Find exact expected rule in Obsidian design/spec note.
- Extract a one-line acceptance statement (example: "Poeira gives permanent reader return, not permanent activations").

2. Locate implementation chain
- Trace from rune data to effect and runtime execution:
- rune resource: resources/runes/**/rune_*.tres
- effect resource: resources/effects/rune_effects/ge_*.tres
- action/condition/selector scripts: scripts/effects/**
- runtime host: scripts/logic/reader.gd, scripts/logic/rune_instance.gd, scripts/logic/battle_context.gd

3. Identify where text is built (tooltip bugs)
- For effect sentence composition, inspect:
- scripts/effects/game_effect.gd
- scripts/effects/actions/action_*.gd get_description/get_description_with_context
- scripts/effects/value_resolver.gd
- scripts/effects/value_per.gd
- scripts/effects/slot_filter.gd
- For rune/slot tooltip containers, inspect:
- scripts/ui/tooltip_builder.gd
- scripts/core/tooltip_texts.gd

4. Identify where highlights are built (highlight bugs)
- Inspect preview/highlight sources:
- condition.get_highlight_slots
- selector.get_preview
- action.get_value_source_slots
- game_effect.get_all_highlights
- Ensure value-source highlight matches the same inputs used by runtime resolve().

5. Branch by bug type
- Behavior mismatch (mechanics wrong):
  - fix action execution/runtime state keys first
  - update resource binding (.tres) to the correct action/condition/selector
- Text mismatch (tooltip sentence wrong):
  - fix get_description composition order with minimal blast radius
  - prefer targeted formatting in the specific action over global wording changes
- Highlight mismatch:
  - fix get_value_source_slots/get_preview to mirror execution logic
- Modifier interaction bug:
  - verify enhancer/slot states/residue side effects
  - avoid direct manager coupling; keep EventBus boundaries

6. Keep data-driven parity
- If effect wiring is generated by script (example: tools/generate_set3_runes.ps1), update generator too.
- Do not leave manual .tres fix that will be overwritten by next generation.

7. Validate
- Run diagnostics for touched files (get_errors).
- Sanity-check final sentence rendering path for affected tooltip.
- Confirm no unrelated APIs changed.

8. Document
- If behavior changed to match design, append concise update to Obsidian impl roadmap.

## Decision Checklist (Fast)

- Is this a design mismatch or implementation bug?
- Is the wrong text coming from action, resolver, per-source, or tooltip wrapper?
- Are highlights computed from same source used by execution?
- Will generator scripts overwrite this fix?
- Are permanent vs temporary buffs stored in correct dictionary keys?

## Quality Gates Before Finish

- Bug reproduction path identified and explained
- Minimal patch applied (no unrelated refactor)
- Affected tooltip/effect text now matches expected grammar/order
- Runtime behavior matches spec intent
- Diagnostics clean for changed files
- Generator parity updated (when applicable)

## Suggested Search Commands

```powershell
rg -n "rune_<id>|<rune_name>|ge_<effect_name>" resources scripts tools
rg -n "get_description\(|get_description_with_context\(|get_all_highlights|get_value_source_slots" scripts/effects scripts/ui
rg -n "ValueResolver|ValuePer|SlotFilter|selector|condition|action_move_reader|activation_bonus|reader_return_bonus" scripts
```

## Output Format For Debug Sessions

When using this skill, return:
1. Root cause in one sentence
2. Files changed
3. Why this fix has low regression risk
4. What was validated
5. Obsidian docs touched (if any)
